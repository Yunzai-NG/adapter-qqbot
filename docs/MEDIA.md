# 图片地址

QQ 拉图是服务器行为，因此图片地址必须公网可达。适配器按链路取址，前一级不可用才走下一级。

## 三级链路

| 顺序 | 通道    | 图片去向                                     | 生效条件                          |
| -- | ----- | ---------------------------------------- | ----------------------------- |
| 1  | 自定义图床 | 插件 `imageToUrl` 返回的地址                    | 插件用 `ctx.provide` 交出函数；未安装则公网直链原样使用 |
| 2  | 官方图床  | QQ 素材库，换 `qqbot-media://` 引用              | 官方图床开启、配额未满                   |
| 3  | 框架图床  | 内置 `/plugin/adapter-qqbot/file/:name` 路由 | 文件服务地址公网可达                    |

全链路都不可用时图片降级为文本占位，日志逐级说明失败原因。

Markdown 图片无法走富媒体接口，需以 `![摘要 #宽px #高px](url)` 嵌入；平台要求显式声明尺寸，适配器会自动解析图片宽高。

## 配置

三个配置项（官方图床 / 文件服务地址 / 图片保存时间）见 [README 配置 → 图片](../README.md#图片)。

> 旧配置里的「图床类型」「图床脚本路径」已移除，打开面板保存一次即自动迁移：选过框架图床的按关闭官方图床处理，脚本路径直接丢弃。

## 媒体整形（可选依赖）

出站字节在「拿到之后、上传之前」统一过一道整形，实现位于 `src/media/transform.ts`，接点有三处：群聊 / 单聊富媒体上传（`MediaUploader.upload`）、频道 multipart 图片（`send.ts`）、Markdown 图片取址（`send.ts`）。

### 图片压缩（sharp）

三条链路各有自己的阈值，语义都是「超过才压」，没超的原样发送、不损画质：

| 链路 | 阈值 | 来源 |
| -- | -- | -- |
| 频道 multipart 图片 | `频道图片压缩上限`（默认 4 MiB） | 频道接口未公开图片上限，由配置决定 |
| 群聊 / 单聊富媒体图片 | 20 MB（平台软限） | 超过会被降级成文件卡片，故提前压回软限内 |
| Markdown 官方素材库 | 10 MB（平台硬限） | 超过直接拒收，故压到硬限内；仍失败则回退框架图床 |

策略是**先降质量、再缩边长**：

| 步骤 | 动作 |
| -- | -- |
| 1 | JPEG 质量 82 → 74 → 66 → 58 逐级尝试 |
| 2 | 仍超限则边长按 100% → 78% → 60% → 45% 逐级缩小，每档重跑质量阶梯 |
| 3 | 带 alpha 的图先试 PNG（调色板 + 最高压缩）保住透明，装不进上限再压白底转 JPEG |
| 4 | 全部失败则按原图发送并记一条 warn |

跳过的类型：动图 GIF（转码会丢动画）、SVG（矢量，重编码反而更大）。压缩后文件名扩展名同步改成 `.jpg` / `.png`，避免平台按扩展名判类型出错。

### 语音转 SILK（silk-wasm，必要时借 ffmpeg）

QQ 语音只认 SILK，`record` 段按下列顺序处理，任一步失败都退回原样上传：

1. 已经是 SILK → 直接上传
2. WAV / pcm_s16le → silk-wasm 直接编码（WAV 采样率传 0，由头部解析）
3. mp3 / amr / ogg / m4a → `ffmpeg -f s16le -ac 1 -ar 24000` 解成 PCM，再编码
4. 都不成立 → 原样上传 + debug 日志

ffmpeg 通过 `execFile` 以参数数组调用（不经 shell），临时文件写在系统临时目录并在 `finally` 清理，单次超时 20 秒。找不到 ffmpeg 时只探测一次，之后永久降级；宿主自带二进制不在 PATH 上时用 `FFMPEG_PATH` 指定。

语音直链若扩展名不是 `.silk`（例如把收到的语音再转发），适配器会跳过「平台转存」，先在本机取字节转码再分片上传 —— 否则平台拿到 wav / amr 会当普通文件处理。

### 降级矩阵

| 缺失 | 影响 |
| -- | -- |
| `sharp` | 超限图片原样发送 |
| `silk-wasm` | 语音一律原样上传（不再尝试转码） |
| `ffmpeg` | 仅 WAV 可转 SILK，其他格式原样上传 |

## 自定义图床（插件实现 `imageToUrl`）

方向是适配器调用插件，不是插件调适配器。在插件里实现 `imageToUrl` 并用 `ctx.provide` 交出，适配器需要地址时会先问它：

```js
import { definePlugin } from "@yunzai-ng/core"

export default definePlugin({
  name: "my-image-host",
  setup(ctx) {
    ctx.provide("qqbot.imageToUrl", async (file, opts) => {
      // file: http(s) 链接 / 绝对路径 / base64:// 是字符串，渲染产物是 Buffer
      // opts: { filename?, mime? }
      if (typeof file === "string" && file.startsWith("http")) return file

      const url = await uploadToMyCdn(file, opts)
      if (!url) return undefined        // 这次处理不了，交给官方图床
      return url                       // https://cdn.example.com/xxx.png
    })
  }
})
```

| 项      | 说明                                                        |
| ------ | --------------------------------------------------------- |
| 服务键    | `"qqbot.imageToUrl"`（即 `adapter-qqbot` 导出的 `CUSTOM_IMAGE_KEY`） |
| `file` | `http(s)` 链接 / 绝对路径 / `base64://` 为字符串，字节为 `Buffer`        |
| `opts` | `filename`（含扩展名）、`mime`                                   |
| 返回值    | `http(s)://` 或 `qqbot-media://`；`null` / `undefined` / 空串表示交给下一级 |

### 行为细节

- 只在需要地址时调用：图片本身是公网直链、或该消息用不到地址时插件不会被打扰
- 返回值只认 `http(s)` 与 `qqbot-media://`，相对路径判无效并继续下一级（否则会变成裂图）
- 抛错按「本次不可用」处理：记一条 warn 后走官方图床，不中断发送
- 每次取址都现查服务表，插件后加载、面板热重载、卸载立即生效，不用重连账号
- `127.0.0.1` / 内网地址 QQ 拉不到，适配器会本机下载字节后再交给官方 / 框架上传
- 内核不支持全局 `Bot`，所以没有 `Bot.imageToUrl` 这种写法；交接一律经 `ctx.provide` / `ctx.inject`

### 现成实现：ImageBed-Plugin

不想自己写一级图床时，直接装 [ImageBed-Plugin](../../ImageBed-Plugin/README.md)：它已经实现了 `qqbot.imageToUrl`，按配置的优先级把图片转存到你自建或第三方的图床，转不了就返回空值，交给适配器继续往下走。

1. 面板 → 插件市场 → 搜索 `ImageBed-Plugin` 安装；装完保持「接管 QQBot 自定义图床」开启（`qqbot: true`，默认值）
2. 在「图床优先级」里排好顺序，只启用你有权使用的通道 —— 能用自己的 COS、CNB 仓库或自建 HTTP 图床时优先用它们，公共图床的容量与存活由对方决定
3. 确认对应场景的 Markdown 已开启且不是 `legacy` 模式；不走 Markdown 的普通图片（富媒体）不经过这一级

接入后的取址顺序：

```text
图片需要地址
  → ImageBed 的 imageToUrl（自定义图床）
      → 已是公网链接且开着「公网直链直接复用」：原样返回
      → 否则按优先级尝试已启用、凭据齐全的图床；全部失败返回空值
  → 官方素材库（qqbot-media://）
  → 框架文件服务
```

几个容易踩的点：

- 服务表不允许两个插件注册同名服务。`qqbot.imageToUrl` 已被别的插件占用时，ImageBed 只记一条 warn 不接管，需停用冲突插件后在面板重载它
- 它不碰官方素材库，也不参与素材库的 100 张配额与过期清理，两级互不干扰
- 它自己的单张大小、超时、并发（默认 20 MiB / 30s / 2 并发）是插件内配置，与适配器的「频道图片压缩上限」无关；适配器压缩发生在取址之前，交给它的是压缩后的字节
- 只提供地址，不代发消息：返回的链接最终由适配器写进 Markdown 或交给富媒体上传

## 官方图床

把图片预上传到 QQ 素材库，Markdown 里引用平台返回的 `qqbot-media://` 链接。**不依赖公网地址**，内网部署、没有穿透域名的机器人也能正常显示图片。

上传对插件透明：申请上传任务拿直传地址 → 直传二进制 → 确认完成换回引用链接，全程在发送前自动进行，失败自动降级。

平台限制：

- 单张 ≤ 10MB，仅 `png / jpeg / gif / webp`
- 单机器人 100 张，引用滑动过期（被消息引用即顺延，90 天未引用才失效）
- 适配器按内容哈希本地去重，同一张图在保存时间内只传一次

### 配额与清理

| 环节   | 行为                                                           |
| ---- | ------------------------------------------------------------ |
| 保存时间 | 默认 `14400`（4 小时，与上传任务有效期对齐），上限 `7776000`（90 天）；同时是去重有效期与清理判定线     |
| 定时清理 | 连接成功后启动，按保存时间的 1/4（最短 5 分钟、最长 24 小时）删超期图；连接后 30 秒补跑一轮，断开即停止 |
| 配额满  | 删超期旧图后重试一次；若全都还在保存时间内，告警并回退框架图床                              |
| 释放节流 | 释放动作 5 分钟内只做一次，期间再遇配额满直接交给框架图床，避免每张图白跑一次列表 + 删除              |

100 张上限是给发图量大的机器人准备的 —— 每条消息里新出现的图片都占一张，靠「图片保存时间」滚动清理才能把配额让给新图。删除不影响已发送的消息（平台发送时已转存副本），只让引用链接失效；适配器会同步失效本地缓存，同一张图再发会重新上传。

## 框架图床

把图片发布到内置的 `/plugin/adapter-qqbot/file/:name` 路由，供 QQ 服务器拉取。

- **文件服务地址**是该路由的对外基址，留空时用内核面板的公网地址
- 必须公网可达。`localhost` / `127.0.0.1` / `10.x` / `172.16-31.x` / `192.168.x` / `[::1]` / `*.local` 以及只能内网解析的单标签主机名（如 `myserver`）都会被直接跳过 —— QQ 拉不到，发出去就是裂图。保存配置时面板会给出提示
- 文件保留 5 分钟（QQ 渲染消息时即刻拉取），最多驻留 100 个，超限自动淘汰
