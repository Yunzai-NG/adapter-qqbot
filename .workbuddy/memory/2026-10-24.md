## adapter-qqbot：Webhook 回调地址校验失败的可观测性改造

- 定位结论：Ed25519 签名实现正确（以开放平台文档标准用例 secret `DG5g3B4j9X2KOErG` 比对，
  `87befc99…652c706` 完全一致）。「保存失败/校验不通过」的真实病因集中在三处：
  回调地址填错（`listenPath` 是死配置，原日志会误导）、账号未启动或非 webhook 模式导致
  registry 为空返回 404、反代/证书/header 剥离。
- `src/webhook.ts`：`createWebhookHandler(handlers, logger?)` 增加 logger 入参；
  新增 `WEBHOOK_ROUTE_PATH` / `WEBHOOK_CALLBACK_PATH` 常量；op=13 通过打 info，
  缺 `X-Bot-Appid`、AppID 未注册、payload 缺字段、op=0 签名失败、未知 op 均打 warn
  （附 ip、UA、原始体片段）；payload 非对象或 op=13 缺字段改返回 400 而非签垃圾值。
- `src/bot.ts`：webhook 模式启动时输出完整回调地址（`host.server.publicUrl + WEBHOOK_CALLBACK_PATH`），
  并对 http 地址、回环地址、`server.enable=false`、`listenPath` 与实际路由不一致分别告警，
  附本机自测 curl；断开时提示重新校验将 404。
- `src/index.ts`：路由用 `WEBHOOK_ROUTE_PATH`，日志改为完整回调路径。
- 新增 `src/webhook.test.ts`（7 例，含官方黄金签名值）。`tsc -b`、`tsc -p tsconfig.test.json`、
  eslint、vitest（71 通过）全绿。vitest 有 3 条 EPERM 报错来自宿主 fs shim 的临时 SSR 缓存，属环境噪声。
- 未改动行为：`listenPath` 配置保留（仅告警）；registry 仍在 `connect()` 内注册的时序问题未动，
  如需彻底解耦（setup 阶段预注册）待确认后再做。

## 同一日：Webhook 安全加固（评审截图提出的两点）

- 复现确认 **op=13 签名预言机（高危）**：op=13 对任意 `event_ts + plain_token` 签名，op=0 验签同为
  `timestamp + body`，同构 → 两次请求即可伪造任意事件（本地 PoC 成功投递 `AT_MESSAGE_CREATE`
  且 content=`#关机` 并被 ingest）。根因是 QQ 协议本身如此，缓解手段只能是约束入参格式。
- `src/webhook.ts`：新增 `PLAIN_TOKEN_PATTERN`（base62 1~128）、`EVENT_TS_PATTERN`（纯数字 1~16），
  不符即 400 并 warn；op=0 增加时间戳新鲜度校验（±300s，兼容秒/毫秒）+ 事件幂等去重
  （键 `appid:t:eventId`，容量 2048，重复返回 `200 duplicate`）。
- `src/ed25519.ts`：`verify()` 由 `===` 改为长度校验 + `crypto.timingSafeEqual`。
- `src/webhook.test.ts` 扩到 12 例（新增：拒绝为 JSON 体签名、非数字 event_ts、平台真实 token、
  过期时间戳、重复投递只投递一次）。`tsc -b`、`tsc -p tsconfig.test.json`、eslint 全绿，
  vitest 93 例通过；PoC 重跑：op=13 返回 400，攻击链断在第一步。
- 未做：op=13 按 IP 限流、是否需要配置开关临时关闭 op=13（例如长期不配置回调时可关闭）。
